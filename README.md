# Шпаргалка на защиту: запуск ETL-проекта с нуля


### 1. Показать архитектуру (ДО запуска кода)

Сначала нужно объяснить логику, пока в базах пусто.

* Открываю **`etl_process.bpmn`** в Camunda Modeler. Показываю процесс извлечения, ветвления (exact, pattern, fuzzy) и откат транзакций.
* Открываю **`er_diagrams.md`**. Показываю ER-диаграммы: структуру источников (`src_projects`, `src_hr`) и схему «звезда» в хранилище (`dw_company`).

### 2. Снести и пересоздать базы (MySQL)

Выполняю скрипты в терминале. Они сами сделают `DROP DATABASE IF EXISTS` и создадут пустые таблицы.

```bash
mysql -u root -p < 01_src_projects_schema.sql
mysql -u root -p < 02_src_hr_schema.sql
mysql -u root -p < 03_dw_schema.sql

```

### 3. Сгенерировать сырые данные

Нужно наполнить источники кривыми данными, чтобы алгоритму было с чем работать.

* **Важно:** проверить, что установлен коннектор (`pip install mysql-connector-python`).

```bash
python 04_generate_data.py

```

*Что сказать преподу:* «Скрипт закинул по 51 записи в обе БД и сгенерировал эталон `ground_truth.csv`. ФИО намеренно искажены: транслит, опечатки, разный порядок слов».

### 4. Запустить сам ETL-конвейер

* **ВНИМАНИЕ:** перед запуском проверить, что в `main_etl.py` в словаре `DB_CONFIG` вбит мой актуальный пароль от базы!

```bash
python main_etl.py

```

«Скрипт извлекает сырые данные, прогоняет их через модуль `fio_match.py` (чистка + алгоритм Дамерау-Левенштейна), формирует "золотые записи" и одной транзакцией заливает всё в хранилище».

### 5. Показать результаты в Хранилище

Открываю MySQL Workbench, закидываю туда скрипт **`05_check_queries.sql`** и выполняю.

* Обязательно показываю последний запрос: там сводная аналитика (средняя зарплата + премия по должности). Это главное доказательство, что факты из HR-базы и базы проектов успешно склеились через каноническое ФИО.
