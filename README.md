# ETL Pipeline & Entity Resolution: Интеграция гетерогенных источников в аналитическое DWH

> **Учебный проект / Лабораторная работа** по дисциплине «Инженерия данных» (Data Engineering / Data Warehousing).  
> Разработка сквозного ETL-пайплайна с модулем разрешения сущностей (Entity Resolution) для устранения дублирования и сборки корпоративного DWH.

---

## 📌 Архитектура проекта

Проект демонстрирует интеграцию разнородных данных из систем `src_projects` (учёт проектной деятельности) и `src_hr` (кадровые начисления) в централизованное аналитическое хранилище `dw_company` по схеме «звезда».

В пайплайне реализован многокритериальный алгоритм склейки записей (Exact, Pattern, Fuzzy match на основе расстояния Дамерау-Левенштейна)[cite: 1], проверка качества данных (Data Quality Gate)[cite: 1] и атомарная загрузка фактов и измерений в единой транзакции[cite: 1].

---

## 📋 Порядок демонстрации и запуска на защите

Ниже приведён строгий регламент демонстрации: что, где и в какой последовательности открывать и выполнять.

### Этап 1. Архитектурный разбор (до запуска скриптов)

* **1. Модель процесса в BPMN**
  * **Где открывать:** Camunda Modeler.
  * **Файл:** `etl_process.bpmn`.
  * **Что показывать:** Архитектуру извлечения из источников, этапы параллельного парсинга, три ветки матчинга (точное, по паттерну, нечёткое)[cite: 1], обработку пограничных случаев и изолированную подсистему отката транзакции при ошибках[cite: 1].

* **2. Схема структуры данных (ERD)**
  * **Где открывать:** Любой Markdown-вьюер / VS Code / GitHub.
  * **Файл:** `er_diagrams.md`.
  * **Что показывать:** Нормализованные реляционные модели источников `src_projects` и `src_hr`, а также аналитическую схему «звезда» в целевом DWH `dw_company`.

---

### Этап 2. Сброс и инициализация баз данных

* **3. Развёртывание чистых схем в СУБД**
  * **Где выполнять:** Терминал / командная строка (Bash / PowerShell) или вкладка запросов в MySQL Workbench.
  * **Файлы:**
    1. `01_src_projects_schema.sql` — сносит и заново создаёт таблицы первого источника.
    2. `02_src_hr_schema.sql` — пересоздаёт таблицы кадрового источника.
    3. `03_dw_schema.sql` — инициализирует структуру хранилища (факты, измерения, журнал `etl_run_log`).

---

### Этап 3. Генерация синтетических данных

* **4. Наполнение источников грязными данными**
  * **Где выполнять:** Терминал.
  * **Файл:** `04_generate_data.py`.
  * **Что происходит:** Заполнение таблиц исходных БД записями с умышленными искажениями (транслитерация, перестановка ФИО, опечатки, инверсия регистра) и формирование контрольного файла `ground_truth.csv` для последующей оценки точности.

---

### Этап 4. Конфигурация и запуск конвейера

* **5. Проверка настроек подключения**
  * **Где открывать:** Любой текстовый редактор / IDE.
  * **Файл:** `main_etl.py`.
  * **Что делать:** Убедиться, что параметры подключения к локальной СУБД в конфигурационном блоке совпадают с рабочими доступами.

* **6. Запуск пайплайна**
  * **Где выполнять:** Терминал.
  * **Файл:** `main_etl.py`.
  * **Что происходит:** Модуль связывается с `fio_match.py`, производит нормализацию, создаёт канонические записи персон в `dim_person`, рассчитывает метрики и транзакционно загружает факты в DWH[cite: 1].

---

### Этап 5. Проверка витрин и защита результатов

* **7. Верификация загрузки и аналитика**
  * **Где открывать:** MySQL Workbench / DBeaver / консольный клиент MySQL.
  * **Файл:** `05_check_queries.sql`.
  * **Что показывать:**
    1. Таблицы аудита загрузки и журнал `etl_run_log`[cite: 1].
    2. Таблицу сопоставлений `dim_person` и сформированные алиасы[cite: 1].
    3. Итоговый аналитический SQL-запрос, склеивающий факты зарплат из кадровой системы и факты назначений из проектной системы в разрезе канонических персон.
